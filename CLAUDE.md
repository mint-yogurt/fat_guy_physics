## Project

TypeScript browser game on the `web-port` branch (npm workspaces, Node 20+). `README.md` = controls, status, feature behavior, known gaps. `DESIGN.md` = design intent. `ideas` and `NEW SHIT TO ADD.txt` = the user's scratch notes, ignore unless asked.

Commands (repo root): `npm run dev` (client, :5173), `npm run typecheck`, `npm test` (vitest, `packages/*/src/**/*.test.ts`), `npm run build`. URL flags: `?gl`, `?radius=N`, `?debug=0|1`, `?save=0` (no load/save), `?reset=1` (wipe the save; debug kit is only granted to a new game).

**Ignore these (legacy / generated / vendored):** `src/`, `CMakeLists.txt`, `cmake/`, `build/`, `third_party/` (the old C++ build; the web port ports from it, comments say "ports src/X.cpp"; only read the C++ if a task says to match it), `tools/golden/` (reference data for shared tests: if a test using `golden.json` fails the code is wrong, never regenerate it), `node_modules/`, `packages/*/dist*`, `*.tsbuildinfo`, `package-lock.json`, `assets/` binaries.

## Packages

- `packages/shared` (`@fgp/shared`): the simulation. **No DOM, no three.js, no browser APIs** (tsconfig has no DOM lib, so the future Node server can run it). No `enum`s (use `const` objects). Fixed timestep, allocation-free hot paths.
- `packages/client` (`@fgp/client`): Vite + three.js (import from `"three/webgpu"` only, never `"three"`) + `jolt-physics`. Rendering, input, UI, Jolt bodies.
- `packages/synth` (`@fgp/synth`): sound synth (patch code -> samples), used by the client's `audio/`. Own README and demo (`npm run synth`).
- `@fgp/server`: not written yet.

## shared/src (the sim)

- `sim/world.ts` (~1500 lines, `World`): ground-tile streaming (`update`, `drain`; one tile per chunk column, key `chunkKey(cx, 0, cz)`), ground queries (`groundHeight`, `groundSurface`, `groundNormal`, `isSolid` shim, `groundTriangles`, `hasChunkAt`), trees (`getTree`, `treesNear`, `chopTree`, `stripFoliage`), props (`propsNear`, `harvestProp`), vegetation spawn (`spawnVegetation`), `raycastScene`. **No digging, no voxels** (an old version of the game, see DESIGN.md). Grep for the method; do not read whole.
- `sim/player.ts` (`Player`): walk/ragball/skating movement, look state, `PlayerInput`. `sim/skate.ts` (`SkateState`): skateboard riding, called from `Player.updateSkating`.
- `sim/collision.ts`: voxel AABB/sphere sweeps (near-verbatim C++ port; epsilons are deliberate). `sim/sceneQuery.ts` (`SceneSolidQuery`): terrain + oriented cylinders (felled logs) + snowbank mounds as one solid query. `sim/mound.ts`: snowbank mesh as a height field (`MoundList`, `moundHeight`). `sim/constants.ts`: `VOXEL_SIZE` (10 cm cell the collision/placement code still counts in), `CHUNK_SIZE`, `FIXED_TIMESTEP`. `sim/chunkSource.ts` (`buildChunk` -> `ChunkResult` = lattice + tile vertices), `chunkKey.ts`, `time.ts`: tile generation seam, key packing, clock.
- `items/inventory.ts`: `ItemType` (Stick, Leaf, Log, Trampoline, Skateboard, Snowball, XmasLights, Rock, 3 containers, MountainLightning, Eggnog, Coal, Goo, Metal, Candy, Toobifer, Plywood, Wheel, Ladder, Spring, SpringShoes, FishingRod), `ITEM_NAMES`, `MAX_STACK` (255), `Inventory` (slot 0 = Unarmed; an empty hotbar slot also counts as unarmed, `isUnarmedSelected`; hotbar 1-8, 16-slot backpack, `version` bumps on change).
- `items/avatarPose.ts`: `AvatarPose` (held item + action + throw charge; packs to 4 bytes for multiplayer), `HoldStyle` per item (Blade/Carry/Pinch/Empty), swing cycle constants, `ThrowWatcher`.
- `items/snowball.ts`: rolled snowballs (`Snowball`/`SnowballField`: roll, grow on snow, settle as terrain features, ball-ball collision, shoved by walkers via `pushedBy`/`yieldTo`, harvest/shrink, 5-min despawn), `ThrownSnowballs` (put throws + bursts), `TrunkQuery`.
- `items/rock.ts`: rocks = heavy balls in the same `SnowballField` (`STONE` `RollMaterial`; `placeRock` for the world's, `spawnRock` for thrown). World places them via `PropMetrics.dynamic` -> `ChunkSink.onRockPlaced` -> `WorldRenderer.onRock` (main.ts). `Snowball.shove`/`pushedBy(..., walkerMass)`/`reaction` = weight-aware hits. Drawn by `snowballView.ts`.
- `items/rolledItems.ts`: items used like a rock (rock, eggnog carton): `ROLLED_ITEMS` rows (material + radius), `rolledItemOf`, `itemOfBall`, `spawnRolled`. New one = a row + a mesh (`snowballView.ts`).
- `items/vessel.ts`: can of mowden lightning (item id `mountain_lightning`) + goo: `VESSELS` (throw speeds, burst speed, splash, stain), `Shake` (LMB), `ThrownVessels` (flight; `splats` burst, `landings` become pickups). Client: `render/vesselView.ts`, `render/gooMaterial.ts` (slime material, `GooStains`), `GOO_BURST` in `snow.ts`, `burstVessel` in `main.ts`.
- `items/rope.ts`: xmas lights/rope. `RopeSpec` (`XMAS_LIGHTS`), `planRope`, `Rope` (XPBD chain, terrain collision, pulls tied `RopeBody`s), `RopeField`, `BallRopeBody`, `PlayerRopeBody` (the hand: the string being placed is a live rope from its first tie to the player, `runLiveRope` in `main.ts`). Add a new rope kind = new `RopeSpec`.
- `sim/elastic.ts`: **the one elasticity engine**: `ElasticMaterial` + `elasticForce` (spring, hardens past max strain), `ElasticCollider` (anything bumpable) + `boxPushOut`/`spherePushOut`. Ropes (`RopeSpec extends ElasticMaterial`) take colliders in `step`; `sim/playerBody.ts` = the player's. New elastic thing = material + shape, no new physics. `Player.applyImpulse` = shove from outside.
- `items/fishing.ts`: **fishing rod**. `FISHING` = the rod's settings (`maxLineLength` = 3x xmas lights' reach, charge time, arc, reel speed...; documented in README "Fishing rod"), `Fishing` (cast/charge/reel state, hook snags `PickupField` items, reeled in -> inventory), `planCast`/`castPath` (aim line). Test: `fishing.test.ts`. Held with the Blade style; `leavesHandOnThrow` keeps the rod in the hand on a cast.
- `items/itemCursor.ts` (`ItemCursor`): the stack on the mouse; click/cancel rules over any `ItemGrid` (interface in `inventory.ts`: `Inventory`, `ContainerStorage`, `CraftingBench`). `items/container.ts`: the 3 containers (`CONTAINER_ITEMS`, `ContainerField` = contents by prop id, `inContainerReach`); they are world props (`World.addProp`/`removeProp`, placed ones persist per chunk column). `items/crafting.ts`: `RECIPES`, `RecipeBook` (item types ever held = recipes known; saved as `PlayerSave.seen`), `CraftingBench` (growing `_ + _` boxes; `craft(cursor, n)`; `cycle` is the stub for a recipe-list UI). `items/springShoes.ts`: `SpringStride` (shoes worn while selected: stepping leaps, landing rebounds, mat gain; `bounds`/`wornOut` = wear stub, lifetime infinite); called in the `main.ts` substep loop after `trampolines.afterPlayerStep`; shoes drawn on the feet by `playerModel.ts` (`placeShoes`, `Limb.sole`).
- `sim/propDamage.ts`: props made of parts (snowmen): `PROP_DAMAGE` per blow, `sectionAtHeight`, `sectionTouching`, `propColliders` (solid cylinders for the player and `TrunkQuery`). Part data = `PROP_SECTIONS` in `worldgen/props.ts`; state/rules = `World.damageProp`, `Prop.broken`; `World.harvestPropYield` also shrinks/removes a `depletes` snowbank. Client: `PropRenderer.onSectionBroken` -> `render/flyingChunks.ts` -> burst (`SnowFlakeBurst` in `render/snow.ts`); `hurtProp` in `main.ts` is the one place every blow goes through.
- Gingerbread houses (`PropMetrics.breakable`): one health bar, `World.damageBreakable`, explode when spent; solid as a box (`propBox`, `SceneSolidQuery.boxes`); one item in `Prop.loot` + 20% a container, both from the biome `lootTable` (`spawns.ts` `placeStructure`, `rollInterior`; rows in `OBJECT_SHEET.interior`). Client: `PropRenderer.onShattered` -> `render/shatter.ts` (triangles fly off); `hurtHouse` in `main.ts`; hit crumbs = `SnowFlakeBurst` with `CRUMB_BURST`.
- `items/placement.ts`: **placing** (ground footprints: mat, gifts). `PLACEMENTS` (per placeable item: footprint, height, `hideHeldInFirstPerson`, `piece?` for building pieces), `placementOf`, `PlacementPlanner.plan` -> `PlacementPlan` (spot, yaw + full quaternion, valid + why). New ground placeable = a row here + a ghost in `placementPreview.ts` + a case in `placeHeld` (main.ts). `items/placementControl.ts` (`PlacementOrientation`): the player's turn of whatever they place (scroll = 45 deg spin steps, R held + mouse = free spin/tilt); main.ts feeds it.
- `items/building.ts` + `items/buildPlan.ts`: **building pieces** (ladder, log, toobifer, plywood, wheel; README "Building"). `PIECE_SPECS` (size, contact face, long axis, `grips` = fixed vs loose, `walkable`, `climbable`), `BuildField` (pieces with pose + `OrientedSolid`, `raycast`, `looseOnes` = fixed pieces nothing holds up, `exportAll`/`restore`, is the `RailSource`), `PieceJoint` (reserved for tape/nails). `aimAtSurface` + `PiecePlanner.plan` lay a piece on the aimed surface (contact face in, long axis along, spin/tilt, slid to touch, volume tested). New piece = a `PIECE_SPECS` row + a `SOURCES` row in `render/pieceMesh.ts` (+ a `PLACEMENTS` row is automatic).
- `sim/climb.ts`: `Rail` (a line to hold; `grabScore`), `railOfPiece`, `ClimbState`, `RailSource`. `Player.climb`/`Player.rails`/`updateClimbing` do the on-rails movement (W/S only, jump lets go, ends hop off). `sim/rotation.ts`: quaternion/3x3 helpers. `sim/sceneQuery.ts` `OrientedSolid` + `SceneSolidQuery.pieces` = walkable settled pieces.
- `items/pickupField.ts` (`PickupField`): dropped items on scalar gravity, E pickup. `items/trampoline.ts` (`TrampolineField`): placed trampoline rules, bounce energy.
- `map/mapData.ts` (`MapData`): explored-area map texture data.
- `save/`: **saving** (README "Saving"). `snapshot.ts` = save types + `sanitize*` (everything read from storage goes through them; items saved by name; `SAVE_VERSION` = migration hook). `gameSave.ts` = `capture/applyPlayer`, `capture/applyWorld`, `worldRevision`. `saveStore.ts` = `SaveStore` interface (+ `MemorySaveStore`); the server will implement it. World's part = `World.exportEdits/importEdits/editRevision` containers = `ContainerField.exportAll/restore`. **New persistent state: add it to the save types, capture/apply, revision, and `save/save.test.ts`.**
- `voxel/` (name left over from the voxel era; no voxels left): `voxel.ts` (`floorDiv`/`floorMod`), `voxelRaycast.ts` (the DDA `raycastScene` steps), `biomeTint.ts` (`Biome`, packing).
- **The ground**: `worldgen/groundField.ts` = the one source of ground height (lattice every `GROUND_STEP` 0.8 m, `TILE_CELLS`, `heightInTile`, `groundHeightDirect`; future crater term documented there). `worldgen/groundMesh.ts` (`buildGroundTile`: tile triangles + per-vertex normal/texture weights/tint/baked sun/spooky; `groundBlend`), `worldgen/gravePits.ts` (open-grave pits: tiles with one are meshed 4x finer with the ground sunk to the box floor). Tuning: `GROUND` + `TERRAIN` in `generationSheet.ts`.
- `worldgen/`: **`generationSheet.ts` = the one file to tune the world** (per-biome spawn tables, terrain shape, object loot/yields). `terrainGenerator.ts`, `biome.ts` (`BiomeField`), `spawns.ts` (placement), `trees.ts` (species metrics), `props.ts` (prop metrics, grave box). `rng/hash.ts`: deterministic hashing (`Math.imul` matters).

## Recipe: adding an item (touch these, then stop exploring)

1. `shared/items/inventory.ts`: add to `ItemType` and `ITEM_NAMES`.
2. `shared/items/avatarPose.ts`: give it a `HoldStyle`.
3. `client/render/heldItems.ts`: mesh builder in that style's frame (`itemAssets.ts` if it needs a loaded GLB).
4. `client/render/hotbarItems.ts` and `pickupRenderer.ts`: hotbar view and ground look (colour/mesh).
5. `client/main.ts`: behaviour (grep `ItemType.Skateboard` / `ItemType.Trampoline` for the existing patterns), and `debug.ts` to grant it for testing.
6. A new kind of hold/action also needs a pose in both `armViewmodel.ts` and `playerModel.ts`.
6b. A placed item on the ground (mat, container): add it to `PLACEMENTS` in `shared/items/placement.ts`, a ghost in `render/placementPreview.ts`, and a case in `placeHeld` in `main.ts`. A building piece (laid on any surface, left to physics): just a `PIECE_SPECS` row in `shared/items/building.ts` and a `SOURCES` row in `render/pieceMesh.ts`; placement, ghost, E pickup, saving and physics follow.
7. Put the item's rules in `shared/` (with a test), not in `main.ts`, so the server can run them. Update README's feature text if behaviour is user-facing.
